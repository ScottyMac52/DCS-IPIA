# Schemas

Version contracts are implemented by the domain models and serializers, rather than standalone JSON Schema files in this directory. Configuration snapshots, editor payloads, portable module snapshots, backup manifests and appearance settings have independent versions. SQLite currently uses migration version 10. See [architecture](../../docs/architecture/README.md), [snapshot serialization](../../src/Heimdall.Dcs/CanonicalSnapshotSerializer.cs), [portable modules](../../src/Heimdall.Dcs/ModuleSnapshotWorkflow.cs) and [database operations](../../docs/operations/database.md). Historical schema-v1 design records are retained under `docs/architecture`.

The [Squadrons native export inspection schema](squadrons/native-export-inspection.v1.schema.json) is an explicit draft format contract for investigating the game adapter. It accompanies the [command inventory](squadrons/command-inventory.v1.json), [all-parameter CSV](squadrons/command-parameters.v1.csv) and [export contract](../../docs/design/squadrons-native-export-schema.md). It validates a parsed inspection representation of the native text, not game acceptance or a JSON file intended for Squadrons.

The [independently observed parameter dictionary](squadrons/native-evidence-audit.v1.json) adds capture-level provenance and before/after comparisons without publishing user profiles or device names. The [engineering evidence matrix](../../docs/design/squadrons-engineering-evidence.md) distinguishes observed values, the failed padding experiment and the isolated successful MFD edit from rules that remain unresolved.

The [shared profile validation definition](profile-validation.v1.schema.json) describes declarative rules used by all four adapters. See the [validation contract](../../docs/design/profile-validation-contract.md) and [packaged definitions](../validation/).
