# Huey release acceptance

The reference is the actual DCS-UH-1H-Huey v3.1.1 release, not output generated by IPIA itself. Its authorized workflow artifact (run 35558158045, artifact 10620389932) was downloaded and verified against SHA-256 `b98da84ab465987091e76902e0017d2f3fd424d99e7af3d7ae6d84730dd921fb`. The inner OvGME archive hashes to `3a4b6a33f8676e2e1872505791938fbb08f8e3ec641c8a74e3b6569b57b06421`; Complete hashes to `cc2b5abca2513c41c1db23c04757b9d7a72aad97e23afb1d1b165ab87562e48b`.

Sources are pinned at consumer commit `77d924cce220355860e8f026cff3524bac531e29`. The source MIT license, captured reference file hashes and release provenance are in `tests/Dcs.Ipia.Tests/Fixtures/HueyParity/PROVENANCE.json`. All 54 source/reference files are independently checked against recorded SHA-256 and length, with no unlisted fixture files allowed. Fixtures are historical test evidence, never deployed as generated IPIA output. Original machine paths remain historical evidence; import does not follow them.

`HueyReleaseAcceptanceTests` uses the real imported consumer metadata, five physical profiles (including three distinct MFDs), actual bundled SVGs and shared Lua, the editor's mapped assignment projection, captured authored labels and reviewed original integration guide. It saves and reopens SQLite, freezes version 3.1.1, verifies Complete, compares repeated bytes, restores into an empty SQLite database, changes a page and restores the earlier snapshot into another empty database. Restore must reproduce the original OvGME and Complete bytes while leaving the edited workspace intact. No mutable checkout, DCS installation or external Common repository is used during snapshot rebuild.

The follow-up correction makes the native Lua command/chord mapping authoritative for explicit UI functions, replacing the four graphic-template relocations and suppressing the 32 unexpected bindings. The acceptance test now requires exact parsed UI equality rather than characterizing an allowed delta. No Huey-specific mapping is embedded in production code. Non-explicit imports retain their previous default composition; explicit module edits and removed history remain preserved.

Mapped control labels now share a geometry- and font-metric-based layout in SVG and PNG. Every variant retains its text and color, wraps before font reduction, fits the authored control width/height and respects its anchor. Category captions use unobstructed space inside their own authored rectangle. This prevents UI labels spilling into neighboring callouts. The current renderer still intentionally differs from the old browser/font encoder, modifier legend wording/colors and old source-build footer. Those are representation differences rather than native assignment changes.

Existing saved modules keep their saved assignments and pinned diagrams; the application does not silently rewrite user edits. Re-import the source to get the corrected initial physical mapping. Independent shared defaults and other module workspaces remain unchanged.

## Reproduce and review

Run `dotnet test tests/Dcs.Ipia.Tests --filter FullyQualifiedName~HueyReleaseAcceptanceTests`. Set `IPIA_PARITY_OUTPUT` to a new report directory if desired; otherwise output goes to the temporary `ipia-huey-parity` directory. The report contains native changes, page dimensions/hashes, archive paths, documentation names, snapshot/archive digests and restore/rollback results. Windows CI uploads it with the generated PNGs as `huey-release-parity`. Full CI retains independent six-layer 80% line and branch gates and actual Windows release-candidate checks.

See [application completion](application-completion.md) for the revised scope. Native UI equality and geometry-bound text are enforced by the merged correction (#129). #83/#9/#111 are closed; current manual controller/DCS acceptance is #189 and release sign-off is #194. They do not justify adding draw.io source creation or legacy repository scaffold generation back to the application finish line.
